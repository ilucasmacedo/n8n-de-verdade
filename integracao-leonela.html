As duas APIs

Groner

REST com JSON e token JWT no header Authorization: Bearer. URL base deste cliente: https://gerasol.api.groner.app.

A consulta da venda é GET /api/Venda/DadosVendaPorPeriodo, com dataInicio e dataFim, como na seção 12.6 da documentação da Groner. O corpo da resposta ainda não foi capturado. POST /api/Conta/GerarToken só serve para obter o token de integração, que entra na credencial do n8n e não no workflow.

Documentação da API Groner

Conta Azul

REST com JSON e autenticação OAuth 2.0. Cobre clientes, produtos, vendas, notas fiscais, cobranças, contas a pagar e a receber.

O acesso exige um app cadastrado no portal do desenvolvedor, que gera o client_id e o client_secret.

Workflows no n8n

Os arquivos ficam na pasta workflows/ e já estão importados no n8n local. Todos começam com LEO - .

WorkflowO que faz
LEO - 00 - ConfigGuarda o tenant da Groner, a URL base, quantos dias buscar e os IDs da Conta Azul. Os outros workflows chamam este no node Config. É o único lugar para mudar quando trocar de conta.
LEO - 01 - Groner - Gerar TokenVocê digita e-mail e senha na hora. Chama POST /Conta/GerarToken e mostra só se autenticou, nome, usuarioid, tenant e expiração. Não guarda execuções no histórico.
LEO - 02 - Groner - Testar TokenChama GET /Conta/MinhaConta com a credencial Groner Token. Se ficar verde, o token funciona.
LEO - 03 - Conta Azul - Testar ConexãoChama GET /v1/pessoas (só leitura) com a credencial Conta Azul OAuth2.
Groner → Conta Azul | MVP - Venda FechadaEsqueleto da especificação: manual, config, buscar vendas, normalizar, IF de venda fechada, mapear, criar venda, registro. Busca, criação e registro de sucesso estão desativados.
LEO - 10 - Groner Vendas → Conta AzulRascunho alinhado ao mesmo contrato: DadosVendaPorPeriodo, interface interna, IF de status e POST /v1/venda desativado. A conta a receber ficou fora do caminho para não lançar o valor duas vezes. As chamadas externas estão desativadas.
LEO - 99 - Error WorkflowQuando outro workflow LEO falha, monta um resumo: nome do workflow, node que falhou, mensagem, horário e link da execução. Só dispara em execuções automáticas e precisa estar publicado.

Por que a configuração fica num sub-workflow: assim o tenant está escrito em um lugar só. Em cada workflow, o node Config é um "Execute Sub-workflow" que chama o LEO - 00 - Config. Os outros nodes leem dali, por exemplo {{ $('Config').first().json.baseUrl }}. Execução manual usa sempre a versão mais recente do Config. Execução agendada usa a versão publicada, então depois de mudar o Config clique em Publish.

Credenciais no n8n

Os workflows procuram estes nomes. A credencial Conta Azul OAuth2 já existe no n8n; falta autorizar a conta se o teste de leitura ainda não ficou verde. A credencial Groner Token ainda precisa ser criada: o token no .env está vazio. Não copie segredo para arquivo de workflow.

Groner Token (Header Auth)

  1. No menu da esquerda, abra Overview, aba Credentials, botão Create credential.
  2. Procure e escolha Header Auth.
  3. No topo, troque o nome da credencial para Groner Token.
  4. Name: Authorization
  5. Value: Bearer seguido do token, com um espaço depois de Bearer. O token sai do workflow LEO - 01.
  6. Clique em Save e rode o LEO - 02 para testar.

Conta Azul OAuth2 (OAuth2 genérica)

Antes, no Portal do Desenvolvedor, crie o app e cadastre como URL de redirecionamento a URL do n8n: http://localhost:5678/rest/oauth2-credential/callback. Ela tem que ser exatamente igual nos dois lados.

  1. Em Create credential, escolha OAuth2 API e dê o nome Conta Azul OAuth2.
  2. Preencha os campos da tabela abaixo.
  3. Clique em Save e depois em Connect my account. Entre com a conta do ERP Conta Azul (não a do Portal do Desenvolvedor) e autorize.
  4. Rode o LEO - 03. O n8n renova o token sozinho: o access_token dura 1 hora e o refresh_token até 2 anos.

Tenant gerasol

O node Config do LEO - 00 já usa o tenant gerasol, com modo_teste verdadeiro. Isso não liga a automação em produção.

  1. Abra LEO - 01, digite e-mail e senha do usuário de integração na hora da execução. Copie o token da saída e apague a senha do node.
  2. Grave o token só na credencial Groner Token, como Bearer mais o token. Não cole o token em arquivo de workflow.
  3. Rode o LEO - 02. O resumo tem que ser o usuário da Gerasol.
  4. Conecte Conta Azul OAuth2 e rode o LEO - 03.
  5. Não publique o agendamento enquanto a tabela de duplicidade não existir.
